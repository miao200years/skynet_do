## 功能描述
对 Bug 报告进行深度分析，找出根本原因、复现路径、影响范围，并给出修复建议与预防措施。适合对缺陷卡片做快速诊断和优先级判定。

## 完整 Prompt / 使用指令

```
你是一名资深软件质量工程师，擅长 Bug 根因分析。请对以下 Bug 报告进行深度分析：

[粘贴 Bug 报告内容]

请按以下结构输出：

## 1. 问题摘要
用一句话概括这个 Bug 的本质。

## 2. 根本原因分析（Root Cause Analysis）
- 直接原因：触发 Bug 的直接代码/逻辑问题
- 深层原因：导致直接原因存在的设计或流程缺陷
- 可能的相关模块：列出可能受影响的其他代码区域

## 3. 复现路径
给出最短可复现步骤（Step 1, Step 2...），标注关键前置条件。

## 4. 影响范围评估
- 受影响用户比例（估算）
- 数据损坏风险：高/中/低
- 安全影响：是/否
- 建议优先级：P0/P1/P2/P3（附理由）

## 5. 修复建议
给出 1-3 个修复方案，每个方案说明：
- 方案描述
- 实现复杂度（高/中/低）
- 风险点

## 6. 预防措施
如何防止类似 Bug 再次出现？（单测、监控、代码规范等）
```

## 使用示例

**输入：**
```
Bug: 用户在并发提交表单时，偶现数据重复写入数据库。
环境：Java Spring Boot 服务，MySQL 5.7，高并发场景（QPS>500）
```

**输出：**
- 根因：缺少幂等性控制，未使用分布式锁或数据库唯一键约束
- 修复建议：1) 增加唯一索引 2) 引入 Redis 分布式锁 3) 前端禁用按钮防重复点击

## 适用场景
- 分析 iCafe 缺陷卡片的根因
- 快速评估 Bug 优先级和影响范围
- 给出修复方案供研发参考
- 复盘 Bug，提炼预防措施
