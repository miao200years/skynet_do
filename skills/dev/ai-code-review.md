## 功能描述
对代码变更（diff）进行全面的 AI 评审，覆盖逻辑正确性、性能问题、安全风险、可读性、测试覆盖等维度，输出结构化评审意见。

## 完整 Prompt / 使用指令

```
你是一名有 10 年经验的高级软件工程师，正在对以下代码变更（diff）进行评审。

[粘贴代码 diff 内容]

请按以下维度逐一评审，每个维度给出 0-10 分并详细说明：

## 1. 逻辑正确性（Logic）
- 核心逻辑是否正确？
- 边界条件处理是否完整（null、空列表、负数、极大值等）？
- 并发/竞态条件是否考虑？

## 2. 性能（Performance）
- 是否存在明显性能问题（N+1 查询、不必要的循环、大对象频繁创建等）？
- 时间/空间复杂度是否合理？

## 3. 安全（Security）
- SQL 注入、XSS、CSRF 等常见漏洞风险？
- 敏感信息（密码、Token）是否明文存储/传输？
- 权限控制是否正确？

## 4. 代码质量（Quality）
- 变量/函数命名是否清晰？
- 函数职责是否单一？是否存在过度耦合？
- 是否有重复代码可以提取？

## 5. 可测试性（Testability）
- 是否新增/更新了对应的单元测试？
- 测试覆盖是否充分（正常路径、异常路径）？

## 6. 总体建议
- Must Fix（必须修改）：列出阻塞合入的问题
- Should Fix（建议修改）：非阻塞但应改进的问题
- Optional（可选优化）：未来可考虑的改进
```

## 使用示例

粘贴 git diff 输出后，AI 会给出各维度评分和具体行级建议，例如：
- "第 23 行：未对 userId 做 null 检查，在 userId 为空时会抛出 NPE"
- "第 45 行：SQL 使用字符串拼接，存在 SQL 注入风险，应使用 PreparedStatement"

## 适用场景
- 提交 iCode 评审前的自查
- 评审他人代码时作为检查清单
- 代码质量培训和案例分析
