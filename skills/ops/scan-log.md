## 功能描述
对系统日志、应用日志、错误日志进行智能分析，快速定位异常、识别模式、评估影响，并给出排查建议和修复方向。

## 完整 Prompt / 使用指令

```
你是一名资深 SRE（Site Reliability Engineer），擅长从日志中快速定位问题。

**日志内容：**
[粘贴日志片段，建议不超过 200 行]

**背景信息：**
- 服务名称：[服务名]
- 日志时间段：[开始时间] ~ [结束时间]
- 触发异常的操作/事件：[描述]
- 已知现象：[用户反馈 / 监控告警等]

请按以下步骤分析：

### 1. 关键异常识别
列出日志中所有 ERROR、WARN、FATAL 级别的条目，按出现频次和严重程度排序。

### 2. 时间线重建
按时间顺序描述事件发展过程，标注关键转折点。

### 3. 根因假设
基于日志提出 2-3 个最可能的根因假设，每个假设：
- 假设内容
- 支持该假设的日志证据
- 置信度：高/中/低

### 4. 影响评估
- 受影响的用户/请求比例（如能估算）
- 数据一致性风险
- 是否需要立即回滚

### 5. 排查步骤
给出接下来的排查 Checklist（按优先级排序），每步说明目的和执行命令。

### 6. 预防建议
如何改进监控告警、日志质量或代码，避免同类问题再次发生？

---
**常用日志分析命令参考：**
```bash
# 按错误级别统计
grep -c "ERROR" app.log

# 提取 ERROR 日志并按时间排序
grep "ERROR" app.log | sort -k1,2

# 统计错误类型分布
grep "ERROR" app.log | awk '{print $5}' | sort | uniq -c | sort -rn

# 提取特定时间段
awk '/2026-05-08 10:00/,/2026-05-08 11:00/' app.log
```
```
