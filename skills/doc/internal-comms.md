# internal-comms

> 撰写各类企业内部沟通文档：3P 进度更新、公司简报、FAQ、事故报告、项目状态。

## 触发场景

需要写以下类型文档时：
- **3P 更新**（Progress 进展 / Plans 计划 / Problems 问题）
- 公司全员简报/周报
- FAQ 常见问题解答
- 事故报告（Incident Report）
- 项目状态更新
- 领导层汇报材料

## 各类型写法指南

### 3P 更新（最常用）

```
结构：
## Progress（本周/本阶段已完成）
- [具体成果，带数字指标]
- [完成的里程碑]

## Plans（下周/下阶段计划）
- [具体可执行的任务]
- [预期完成时间]

## Problems（遇到的问题/风险）
- [问题描述] → [期望的支持/决策]

风格原则：
✅ 具体：用数字量化（而非"有进展"）
✅ 简洁：每条 1-2 句，不超过 5 条
✅ 面向读者：领导想知道"影响是什么"而非"做了什么"
```

**示例：**
```
## Progress
- 完成了支付模块 85%（原计划 70%），提前3天
- 用户注册转化率从 12% 提升至 18%（A/B 测试结果）

## Plans
- 本周完成支付模块并提测（周五前）
- 开始 Q3 功能规划文档（需 PM 介入）

## Problems
- 第三方支付 SDK 文档不完整，导致对接延期1天
  → 需要采购提供联系人或替代方案
```

### 事故报告（Incident Report）

```
结构：
## 事故摘要
- 发生时间、持续时长、影响范围（用户数/业务影响）

## 时间线
- HH:MM 事件描述
- HH:MM 发现/响应/恢复

## 根本原因（Root Cause）
- 技术原因（是什么导致了问题）
- 为什么没有被提前发现（监控/测试盲区）

## 修复措施
- 立即修复（已完成）
- 预防措施（计划中，带 Owner 和 DDL）

## 影响评估
- 受影响用户/请求数量
- 业务损失估算（如适用）
```

### 全员简报

```
风格要求：
✅ 开头用一句话概括本期最重要的事
✅ 用"我们"而非"公司"，增加归属感
✅ 坏消息要坦诚，不要用委婉语掩盖
✅ 结尾给出明确的行动号召或期待

结构：
1. 核心消息（1段）
2. 业务进展（2-3条）
3. 团队/人事动态
4. 下一步期待
```

## 语言风格原则

| 场景 | 语气 | 避免 |
|------|------|------|
| 3P 更新 | 简洁、直接、数据驱动 | 模糊的形容词 |
| 事故报告 | 客观、技术性、不甩锅 | "由于XX的失误" |
| 全员简报 | 温暖、坦诚、包容 | 官僚套话 |
| 领导汇报 | BLUF（结论先行）| 铺垫太多 |

## 快速模板填写

```
写一份3P更新：
- 上下文：[项目/团队名]
- Progress：[用一句话说完成了什么]
- Plans：[下阶段目标]
- Problems：[有没有阻塞项？需要什么帮助？]
```
